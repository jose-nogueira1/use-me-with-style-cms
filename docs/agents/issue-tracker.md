# Issue tracker

Use the existing Linear project: https://linear.app/joses-workspace-1/project/use-me-with-style-platform-37c7b8734a16 . Existing references use the JOS prefix. Both repositories contribute to this project; do not introduce a second GitHub Issues backlog.

This mapping comes from the platform README; live permissions, statuses and label names have not been verified. Before tracker writes, inspect the project through the available Linear connector and reuse its existing vocabulary. If unavailable, draft the spec/tickets locally under `docs/plans/` and report that they are drafts, not synchronized issues. Do not fabricate issue IDs or use local drafts as a competing permanent tracker.

Tickets should identify the affected repository, acceptance criteria, verification, and dependency links. Cross-repository tickets must state the CMS/frontend rollout order. Keep one issue for a small complete change; split larger work into independently verifiable user outcomes. Record the actual issue ID in the branch or PR when one exists.

External PRs are not an enabled triage request surface. GitHub remains the code review and delivery surface. A request to plan work does not itself authorize sending messages to others.
